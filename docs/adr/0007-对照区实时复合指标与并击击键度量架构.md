# 对照区实时复合指标与并击击键度量架构

为在跟打过程中为用户提供低干扰、高信息密度的即时速度与手感反馈，同时精准度量并击输入法（Rime `chord_composer`）下的击键频率与码长，确立了以下度量模型、时序窗口、界面布局与状态生命周期架构决策。

## 1. 并击算一击的度量模型 (One-Chord-One-Stroke Model)

在中文打字与并击社区规范中，跟打成绩的三大核心指标为 **字速（WPM）**、**击速（KPS / 击键）** 与 **码长（Key Length）**，满足关系式 $\text{WPM} = \frac{\text{KPS}}{\text{码长}} \times 60$：
- **并击归一化（Chording Normalization）**：在并击方案（如空明拳、六脉神剑、速录等）下，一次同时按下一组键（如左手 `x+v` 并击、三键 `e+s+f` 并击）在击数度量上**严格计为 1 击（1 Stroke）**，而非拆解为多个物理击键；
- **代数码元映射**：依托 [ADR 0006](file:///home/jackwy/codes/rime/dazitui/docs/adr/0006-基于-rime-schema-的并击指法逆向解析与实时键盘映射架构.md) 中的 `ChordAlgebra` 逆向引擎，过滤手区修饰符（`_`、`+`）后，反查编码中的每个独立逻辑码元天然对应一次击键动作（1 Stroke），实现数学上的绝对精确；
- **回改计入击数**：每次退格（`Backspace`）计为 1 击，真实反映因回改失误消耗的手速。

## 2. 复合指标与 2.0 秒滑动窗口 (Compound Metrics & Rolling Window)

针对用户在练习过程中既想了解“本局预期最终成绩”又想感知“当下爆发手速”的复合诉求：
- **双轨计算体系**：
  - **全局累计平均值**：$\text{Cumulative WPM} = \frac{\text{当前累计正确字数}}{\text{已用时(分)}}$，$\text{Cumulative KPS} = \frac{\text{当前累计总击数}}{\text{已用时(秒)}}$；
  - **即时滑动窗口平滑值**：基于近 2.0 秒窗口内的击键数与正确字数计算 $\text{Rolling WPM}(t)$ 与 $\text{Rolling KPS}(t)$；
- **时序算法复用**：实时即时值计算与成绩视图的速度折线采样算法（`compute_speed_samples`）完全复用同一 2.0s 窗口模型，保障跟打中与打完后的数据口径 100% 严丝合缝。

## 3. 对照区右下角主次双显布局 (Bottom-Right Dual Display)

- **呈现格式**：在对照区（Reference Area）Ratatui Block 的底边框右侧（`title_bottom` 右对齐）渲染：
  ` WPM 120.5 (138) · 击键 5.2 (6.0) `
- **视觉层次与配色**：
  - 标签（`WPM`、`击键`）：使用主题次要色（`palette.muted`）；
  - 累计主值（`120.5`、`5.2`）：使用主题强调色加粗（`palette.accent.bold()`）；
  - 括号即时瞬时值（`(138)`、`(6.0)`）：使用浅强调色（`palette.cyan` / `palette.fg`）；
  - 分隔符（`·`）：使用暗淡色（`palette.muted`）。

## 4. 状态机与生命周期行为 (Lifecycle & State Transitions)

- **就绪态（未开打）**：对照区底边框保持干净，**不显示指标**，避免分散用户阅读赛文原文的注意力；
- **跟打进行中**：敲击第一个键激活计时后，右下角指标平滑浮现，并随终端 100ms 刷新率（10 FPS）实时动态衰减与更新；
- **暂停态（按 Tab）**：计时冻结，指标锁定在暂停时刻的累计值，即时值显示为 `(0)` 或隐藏，并伴随对照区边框状态变更；
- **成绩结算**：跟打完成后平滑过渡到成绩视图，最终 WPM 与击键数值与实时累计读数完全无缝吻合。
