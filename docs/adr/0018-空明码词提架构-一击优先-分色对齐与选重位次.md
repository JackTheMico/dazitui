# ADR 0018: 空明码词提架构——一击优先、分色对齐与选重位次

## 状态
已接受 (Accepted) — 2026-09-27

## 背景与问题 (Context)
在空明码（并击方案）打词与跟打练习中，原词提（`CodeHint`）存在以下三项体验与度量缺陷：
1. **一击字感知缺失**：许多高频双字词（如「好人」）并非词库一击词（需 4 字母 2 击），但其组成字符均为 204 个极速一击字。原词提直接显示不易辨识的 4 字母双手并击码（如 `hr` 对应的复杂并击），而空明码选手在肌肉记忆上更倾向于先后击出两个熟悉的单字一击并击。
2. **左右手手区无视觉分色**：空明码一击字赛文中，左手字与右手字分别使用粉色与黄色高亮，选手能凭借色块瞬时反应手区。但在词组或常规赛文中，词提仅能整体展示单一颜色（双手并击青色或默认色），无法分色指示各字的左右手归属。
3. **重码与非首选位次隐形**：原 ADR 0013 为优化 270 万大词库载入性能，对并击方案清空了候选位次索引（`code_index`）。这导致当某个词并非首选候选时（如 2 选），词提无法知晓其 `rank`，既不提示选重键，也不在击数统计中计入选重击键，造成练习提示与真实输入割裂。

## 决策 (Decision)

### D1 · 优先级梯队：一击词绝对优先
- **第一梯队（一击词）**：若目标词在空明码中是一击词（1 击单并击，如「中国」`Uz`、「可以」`k'`），最高优先保留一击词提示，绝不拆解为 2 击的一击字。
- **第二梯队（一击字转译）**：若该词不是一击词，但其所有字符全部收录于 204 个一击字表中（`KONGMING_1HIT_CHORDS`）：
  - 仅当 `一击字总击数 <= 词库整词码击数` 时进行转译（双字词 2 击 = 2 击触发转译；四字成语词库 2 击 < 逐字 4 击则保护不转译）。
  - 转译后以空格分隔各字编码（如 `h r`、含空格并击字如 `h␣ r`）。
- **第三梯队（词库整词编码）**：保留词库最优整词码。若该词不是首选候选，按 D3 规则追加选重键。
- **第四梯队（逐字全码回退）**：未收录词回退到逐字全码。

### D2 · 左右手独立分色与排版对齐
- `HintCell` 升级为分段渲染模型：词格内部的每个单字按自身手区（`HintHand::Left` / `HintHand::Right`）独立着色（左手粉色、右手黄色）。
- 词格两端用于居中对齐的补白空格及单字间的间隔空格不施加手区颜色（`HintHand::None`）。
- 词格列宽与换行打包锁步机制保持不变（`max(词宽, 码宽)`）。

### D3 · 候选位次显示与真实物理击数度量
- 空明码等纯并击方案保留候选反查索引（`code_index`），准确定位目标词在重码组内的位次（`rank`）。
- **按键直传式选重**：若目标词不在首选（`rank > 1`），在编码尾部直接追加数字键（如 2 选追加 `2`，形成 `oc2`、`bGCw2`）。
- **击数精确度量**：非首选词追加选重键后，总击数计为 `基础并击数 + 1`，忠实反映选手的物理敲击次数，彻底杜绝码长与击键（KPS）失真。

## 后果 (Consequences)
- **正面**：
  - 空明码选手在常规长文与词组练习中能清晰感知一击字的连打路径，手感大幅提升。
  - 左右手分色直观强化左右手交替打字的视觉反馈。
  - 非首选词带有明确的选重位次指示，击数度量与实际按键 100% 吻合。
- **代价与权衡**：
  - 空明码方案载入时保留 `code_index` 会占用约数百兆内存，但载入由后台异步线程完成，不会阻塞 TUI 主渲染循环。

## 补充（2026-11-08）：以当前 XSIME 方案为准的准确性修正

现实运行环境从 `fcitx5-rime` 迁移到 XSIME 后，词提的数据源与可行性判据需要随实际部署方案修正：

- **数据源优先 XSIME 激活方案包**：方案发现顺序改为
  `$RIMES_USER_DIR/schemes/packages/<active>/`（或 `$XDG_DATA_HOME/rimes/...`）→ 其余方案包 → 旧 `fcitx5-rime` 目录；
  同名方案以先出现者为准，避免继续提示旧部署词库中已修正/易主的编码。
  固定码表（`KONGMING_1HIT_CHORDS` / `KONGMING_1HIT_WORDS`）只作兜底：一击词表条目必须经词库确认该码确属此词，
  防止过时条目把重码提示给别的词（例如旧表「看到 ;K」已被「之后 ;K」取代）。
- **一击字来源扩展**：仍以 204 静态表为主（记法简洁且已与 kongmingmas 一致），表外字符若词库确有一击码也参与转译；
  `f=` / `=d` / `a_=` / `=_a` 这类并击逻辑码在提示中还原为实际按键 `f` / `d` / `a␣`。
- **逐字转译计入选重键**：比较时使用「各字击数（含各自选重键）之和」，不再以字符数粗估。
- **选重位次的物理上限**：并击采集器的字母表会占用数字键（空明码为 `7/8/9/0`），这些数字不能用于选重；
  最大可选位次由 `chord_composer/alphabet` 推导（空明码为 6）。超过上限的重码视为不可选，跳过并改用次优可行码。
- **码尾数字不是选重键**：空明码码元本身可含 `7/8/9/0`，`S7`、`Y0` 等仍计 1 击；选重键由 `rank` 显式计入，不再解析码尾数字。
