# 串击方案实时键盘的击键回放时序架构

为区分并击与串击方案在实时虚拟键盘上的视觉语义，确立「同一张键盘图、两种点亮时序」的架构决策。

## 1. 背景与问题 (Problem)

ADR 0006 确立了并击方案的反查映射与实时键盘架构：汉字上屏时经方案反查得到物理键集合，在虚拟键盘上瞬间全量激活并统一衰减。

该架构隐含一个前提——**一次上屏对应一次并击**，反查出的多个键在物理上是同时按下的，因此共用同一时间戳是正确且必要的。

但串击方案（虎码、五笔、小鹤音形、拼音等）不满足此前提：一次上屏对应的是**一串先后按下的键**。而 Linux 终端下 TUI 只能收到上屏文本（见 `docs/research/live-keyboard-display.md` 第 2.1 节），反查出的 N 个键在**同一帧**抵达。若沿用并击的时间模型，串击的 N 个键会同时点亮、同时衰减，视觉上被"拍"成一次并击——串击与并击在键盘图上完全没有区别，用户无法从中获得任何指法节奏信息。

## 2. 决策 (Decision)

**共用同一张虚拟键盘图，仅在「点亮时序」上区分两种方案。**

- **并击方案**（`SchemeDict::chord_algebra().is_some()`，如空明码、麓鸣）：反查出的全部物理键共用同一时间戳，同时点亮、同时衰减。语义为「一次并击同时按下」。
- **串击方案**（无并击指法规则，如虎码）：反查出的 N 个键按回放节奏**依次**点亮，先按下的键先衰减，在同一张键盘图上形成拖尾。

判定沿用 ADR 0006 已有的 `chord_algebra()`：代码库中不存在独立的「串击」概念，串击即「非并击」。不新增设置项，判定全自动。

## 3. 时序模型 (Timing Model)

设 Δ 为「本次上屏时刻 − 上次输入时刻」，N 为本次反查出的键数：

```
interval = clamp(Δ / N, 20ms, 120ms)
第 i 键时刻 = now − (N − 1 − i) × interval     // i = 0..N-1
```

最后一个键落在 `now`，先按下的键时间戳更早，因此在渲染帧上已经衰减——这就是拖尾的来源。

**双端钳制的必要性**：

| 场景 | 未钳制的问题 | 钳制后 |
|---|---|---|
| 快速连打（4 键 / 40ms） | 每键 10ms，肉眼近似同时，拖尾消失 | 抬到下限 20ms |
| 长停顿后打一个字（4 键 / Δ=4s） | 每键 1000ms，最后一个键亮完要 4 秒，像卡带 | 压到上限 120ms |

每次输入（上屏与退格）都会刷新 `last_input_at`；`clear()` 一并重置。

## 4. 被否决的方案 (Alternatives Considered)

- **独立的击键流水日志面板**：在键盘图位置改渲染"最近 N 次上屏的按键流水"。否决——它与 `docs/research/live-keyboard-display.md` 既定的「虚拟键盘 + 反查涟漪」设计不符，且引入了行宽溢出、退格刷屏、面板行数等一批与键盘图无关的新问题。
- **放弃时序区分，串击与并击同样同时点亮**：否决——两者渲染完全一致时，"串击方案自动切换"这一需求本身失去意义。
- **只按整体时长钳制（≤400ms）**：否决——长词（如整词上屏 16 键）每键被压到 25ms，拖尾几乎不可见。
- **按当前实时击键速率推算间隔**：否决——引入对 `Session` 状态的依赖，测试需构造 KPS，收益不抵复杂度。

## 5. 已知局限 (Known Limitations)

- **重复字母**：`active_keys` 为 `HashMap<键名, Instant>`，同一键帽只能保留一个时间戳。码中重复字母（如虎码 `kk`）的两次按压在视觉上合并为一次高亮。修复需改为 `HashMap<键名, Vec<Instant>>`，当前认为收益不抵复杂度。
- **反查失败 / 未配置方案**：不会产生按键，键盘图无键点亮。属于可接受降级——键盘图本身仍在，不像流水面板那样退化为空区域。
- **回退到"真实"击键不可行**：TUI 无法看到输入法组字阶段的物理按键，回放节奏只能由 Δ 推算，不代表用户真实按键分布（例如选重、补码的额外击键不可见）。

## 6. 影响范围 (Scope)

改动仅涉及 `dazitui/src/main.rs`：

- `LiveKeyboard` 新增 `last_input_at` 字段与 `staggered_press_times()`；
- `press_keys()` 新增 `stagger` 参数；
- `handle_text()` 依据 `chord_algebra().is_none()` 决定 `stagger`。

渲染层（`generate_live_keyboard_lines` / `render_live_keyboard`）与布局（`kb_height`）均未改动，两种方案共用。
