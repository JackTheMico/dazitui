# ADR 0014：虎整句词提——连续码模型与真实选重键

- 状态：已实现
- 日期：2026-09-18
- 相关：ADR 0013（万象虎词提：确定性优先的最小击数择优）

## 背景

虎整句（`tiger_sentence`，`schema.name: 虎整句`）是**变长整句**方案：字母连续输入、
由 Kneser-Ney ngram 语言模型分词（`lua_translator@tiger_sentence_translator`），
`speller` 无 `max_code_length`。

dazitui 此前把它跟万象虎一样判为「定长 4 码自动上屏」——因为 `detect_four_auto_commit`
按文件名前缀 `tiger` 命中。二者的击数模型完全不同，导致词提与真实打法不符。

用户诉求：有简词可用时提示简词编码（慢慢 / 一般 / 所以 / 怎么 等）。

## 事实基线（均以官方实现为准）

码表 `tiger_sentence.codes.txt`（15374 行，去重 9896 条）：

| 类别 | 条数 | 说明 |
|---|---|---|
| 单字 | 9794 | 每字 1~4 条码（一简/二简/三简/全码），行序 = 候选位次 |
| 多字词 | **102** | 1 码 29 / 2 码 63 / 3 码 9 / 4 码 1 —— 全是简词 |

「行序 = 选重名次」是码表自述的格式约定，无权重列；102 个简词中有 60 个非首选。

官方 README 与 schema description 的硬规则：

1. 「字母**连续**输入整句编码；空格提交候选」——字词之间不按上屏键。
2. 「有编码时 `;` `'` 数字分别选择码表第 2、3、N 项」——选重键不是空格。
3. 「非首选多字词在任何切分路径中**必须显式选重**」。
4. 「一码段只在整段输入只有一码时合法」——单字母码不能并进多字连续码。
5. 「概率型提交仍永远**不少于三键**」——2 码词必定要补键。
6. `tiger_sentence/option_defaults.tiger_sentence_early_commit: true`。

## 决策

| # | 决策 | 结论 |
|---|---|---|
| D1 | 上屏口径 | **恒算一次提交键**：击数 = 连续码长 + 1。提前上屏是概率性的，恒算绝不小算 |
| D2 | 选重键显示 | **按 `speller/alphabet` 推导真实按键**：第 2 位 `;`、第 3 位 `'`、其余数字；字母表不含则退数字 |
| D3 | 未收录词 | **连续码**：各字取长度 **≥ 2** 的最短码依次相连（一码段规则），不再逐字独立上屏 |
| D4 | 简词优先 | 整词条与连续码比较击数取小；实测简词恒优（3 击 vs 9 击） |
| D5 | 方案判定 | 新增 `sentence_mode`（schema_id/文件名含 `sentence` 或方案名含「整句」），优先级高于 `four_auto_commit` |

## 算法规格

```
候选 A（整词条）: 码表中该词的显式码
    strokes = 码长 + 1
    rank    = 该码组内按行序的位次

候选 B（连续码）: 各字取 len>=2 的最短码依次相连      # 单字词不受此限
    strokes = 连续码长 + 1
    rank    = 1（语言模型分词，按首选计）

择优: min(strokes)，平局取整词条
标记: rank 1 -> ␣ ；rank 2 -> ; （字母表含 ;）否则 2 ；rank 3 -> ' （含 '）否则 3 ；其余 -> 数字
```

## 实测对照（官方 lua `tiger_sentence.decode_full` 逐条验证）

| 词 | 改动前 | 击数 | 改动后 | 击数 | 解码器实测 |
|---|---|---|---|---|---|
| 结果 | `igd␣qem␣` | 8 | `igdqem␣` | 7 | `igdqem` → 结果 ✔ |
| 个人 | `jg␣j␣` | 5 | `jgjr␣` | 5 | `jgj` → 佝 ✘ / `jgjr` → 个人 ✔ |
| 大量 | `m␣ofd␣` | 6 | `mdofd␣` | 6 | `mofd` → 犹事 ✘ / `mdofd` → 大量 ✔ |
| 一般 | `fi·2` | 3 | `fi;` | 3 | `firs` → 一劝 ✘ / `fiirs` → 一般 ✔ |
| 慢慢 | `hh·2` | 3 | `hh;` | 3 | `hh` → 卷(1) 慢慢(2) ✔ |
| 所以 | `m·2` | 2 | `m;` | 2 | `m` → 大(1) 所以(2) ✔ |
| 自己 | `o·2` | 2 | `o'` | 2 | `o` → 是(1) 自己(2) 知道(3) ✔ |
| 习惯性 | 逐字 11+ | — | `zxhkohls␣` | 9 | `zxhkohls` → 习惯性 ✔ |

**关键教训**：一码段规则不是理论约束，实测直接把「个人」拼成 `jgj` 会解码成「佝」。
改动前的逐字回退正好踩在这条规则上——它给的是**打不出目标词的码**。

## 实现

- `SchemeDict` 新增 `sentence_mode` / `select_semicolon` / `select_apostrophe`；
  `detect_sentence_mode()` 与 `read_select_keys()`（读 `speller/alphabet`）。
- `build_hint_for_word_sentence()` / `sentence_continuous_code()`：整词与连续码择优。
- `mark_commit_key()` 改为 `&self` 方法，直接写出要按的键（`␣` / `;` / `'` / 数字）；
  `code_hint.rs` 不再依 `rank` 二次追加 `·n`——**提示串 = 要按的键序列**。
- `primary_or_best()` / `decompose_code()` 增加整句分支，保证击键统计与词提同源。

对万象虎的连带影响（ADR 0013 行为收敛）：字母表含 `;` 不含 `'`（`'` 是其拼音反查前缀），
故 `佳人 jgjr;`（第 2 位）、`伟人 jgjr3`（第 3 位）。既有 `·n` 标注与相关断言已同步更新。

## 回归测试（`dazitui-core/tests/tiger_code_hint.rs`）

- `test_tiger_sentence_jian_ci_wins_over_continuous_code`：遍历码表全部 102 个多字简词，
  断言无一退化成连续码，且击数 ≤ 码长 + 1。
- `test_tiger_sentence_continuous_code_skips_one_letter_codes`：连续码各字段长 ≥ 2，
  期望值与官方解码器一致。
- `test_tiger_sentence_hint_and_stats_share_one_measure`：词提击数 = 统计击数 = 按键序列长度。

## 遗留

1. **连续码的首选性无法在 dazitui 侧验证**：`rank = 1` 是对语言模型的假设。
   31 个样本全部命中，但长尾词可能被其它切分压过。真实校验要跑 lua 解码器。
2. **整句跨词合并未做**：`merge_phrase_hints` 仅在拼接命中词典整词时合并；
   虎整句的连续码本身可跨词，理论上相邻词合并后击数可能更省，未实现。
3. **用户学习库未纳入**：`tiger_sentence.userdb` 会改变实际候选顺序，dazitui 读不到。

## 修订（2026-09-18）：`的` 应为 `u␣` 而非 `u;`

`tiger_sentence.codes.txt` 无权重列，`u` 组含 `的`（第 6 行）与 `工作`（第 2545 行）。
`code_rank` 原先在权重相同时按 `a.word.cmp(&b.word)` 二次排序，按码点「工」<「的」，
把简词「工作」排到单字「的」前面 → 提示 `u;`（第 2 位）。

修正：去掉字典序二次排序，改用稳定排序保持**码表录入顺序**（ADR 0013 D2'）。
连带修正的既有断言：`工作` `u␣`→`u;`；`东西` `r␣`→`r'`；`自己` `o'`(3)→`o;`(2)，`知道` 才是 `o'`(3)。
已用独立脚本按录入顺序复算全部 102 个多字词，与实现输出零差异。
回归测试：`test_tiger_sentence_single_char_yijian_is_first`。
