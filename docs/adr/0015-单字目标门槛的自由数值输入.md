# ADR 0015：单字目标门槛的自由数值输入

- 状态：已实现（2026-09-19）
- 日期：2026-09-19
- 相关：ADR 0010（单字练习目标门槛与单组冲刺统计架构）——本 ADR 部分取代其 §4

## 背景

ADR 0010 为单字专项冲刺引入了「目标击键」与「目标速度」两道放行门槛，但配置方式只有**预设档位轮转**：
设置视图用 ←/→ 循环固定档位，内置单字预览弹窗用 `t` / `w` 循环同一批档位。

档位粒度对刻意练习太粗。用户诉求是能自行设定 `4.3` 击/秒、`115.5` WPM 这类非档位值——
例如「当前稳定在 4.0 击/秒，下一阶段目标 4.3」这种渐进式自我加压，用 `3 → 4 → 5` 的档位根本无法表达。

## 事实基线

改动前的实际状态（均以代码为准）：

| 项 | 现状 | 出处 |
|---|---|---|
| `Settings.target_kps` | `f64`，解析区间 `0.0..=30.0` | `settings.rs:722,1003` |
| `Settings.target_wpm` | **`u16`**，解析区间 `<= 500` | `settings.rs:724,1010` |
| 预设档位 | 击键 `[0,3,4,5,6,7,8,9,10,12,15]`；速度 `[0,40,…,200]` | `settings.rs:745-749` |
| 设置视图 | 「单字目标击键」「单字目标速度」两行，←/→ 轮转预设 | `main.rs:3382-3407` |
| 预览弹窗 | 内置单字赛文预览，`t` / `w` 轮转预设 | `main.rs:3272-3277` |
| 组末判定 | OR 逻辑 `group_kps >= target_kps \|\| group_wpm >= target_wpm` | `session.rs:447` |
| 未达标文案 | 实际值按 `{:.0}` 渲染 | `session.rs:192` |
| 存储 | `~/.config/dazitui/settings`，行式 `key=value` 文本 | `paths.rs:118` |
| 已有先例 | `TextSettingModal` 单行文本弹窗（反查方案 / 上传名称） | `main.rs:1196-1265` |

两条支撑小数门槛的事实：

1. **组级 WPM 本身具备小数分辨率**。以 10 字组计，0.1 WPM 约合 0.026 s，远高于计时精度。
   故 `115.5` 不是装饰性精度，而是可稳定复现的判定边界。
2. **`target_kps` 早就是 `f64`**，且可直接手改配置文件生效；真正阻塞自由数值的只有 `target_wpm` 的整型类型与两处 UI 的轮转交互。

## 决策

| # | 决策点 | 结论 |
|---|---|---|
| D1 | 数值模型 | `target_wpm` 由 `u16` 改为 `f64`；两项统一「最多 1 位小数」，提交即量化（`(v*10).round()/10`），存储与判定均用该量化值 |
| D2 | 输入途径 | 新增**数值输入弹窗**，复用 `TextSettingModal` 骨架；←/→ **保留**预设档位轮转做粗调，设置视图对应行按 `Enter` 打开弹窗 |
| D3 | 预览弹窗入口 | 小写 `t` / `w` 保持预设轮转；新增大写 `Shift+t` / `Shift+w` 打开数值输入弹窗（`Enter` 已被「载入赛文」占用） |
| D4 | 合法性与钳制 | 非数字输入（空串 / 含字母 / 纯符号）→ 静默取消，保持原值；可解析但越界 → 钳制到边界。区间沿用击键 `0.0–30.0`、速度 `0–500`，提为 `TARGET_KPS_MAX` / `TARGET_WPM_MAX` 常量；**`0` 仍表示关闭门槛** |
| D5 | 显示口径 | 击键恒 `{:.1}`（宽度稳定）；速度整数省小数、含小数带 1 位；未达标提示中实际值与目标值同规渲染 |
| D6 | 版本兼容 | 接受旧版读到小数 `target_wpm` 时 `parse::<u16>()` 失败而静默回落为 `0`（关）。不引入双字段、不引入配置版本号 |
| D7 | 适用范围 | 仍仅限**内置单字赛文**；词组赛文与长文不设门槛（ADR 0010 §1 不变） |

## 决策理由

**D1 为何不用整数档位加密替代。** 把档位加密成 `3.0/3.5/4.0/4.5/5.0` 也能让 `4.3` 附近可及，但 ① 档位永远是有限集，用户的真实目标值不落在网格上时问题原样复发；② 档位集合将持续膨胀，`next/prev_preset` 的线性扫描与回绕语义越来越难讲清；③ 击键侧本就是 `f64`，速度侧收紧为 `u16` 缺乏一致的理由。

**D4 为何区分「非数字」与「越界」。** 二者风险不对称：把 `abc` 当作 `0` 会**静默关闭门槛**（用户以为设上了，实际在裸奔）；而把 `80` 钳到上限只是限制，方向安全。分类处理使「输入被丢弃」与「输入被改写」各自明确。错误提示不进弹窗，是为了与既有反查方案 / 上传名称弹窗「回车即生效、Esc 即放弃」的交互契约保持一致。

**D6 为何不做双字段兼容。** 降级方向安全（回落为「不设限」，不会崩溃、不会死锁，击键门槛不受影响，因为 `target_kps` 本就是 `f64`）。双字段方案的代价是两套字段长期共存、必须在代码里持续维护「哪份是真值」的约定，而收益只覆盖「新版本写小数 → 回退旧版本 → 期间恰好在旧版改了别的设置」这一条窄路径。

## 影响

- **类型扩散**：`target_wpm` 的 `u16` → `f64` 需同步修改 `Settings::set_targets`、`Session::target_wpm`、`TargetFailure.target_wpm`、两处 `>=` 判定与全部文案渲染（`session.rs` / `settings.rs`），并更新相关测试断言。
- **已知降级后果**（D6 取舍的代价）：在新版本设了 `115.5`，若退回旧版本且旧版本又保存了任何设置，旧版本的 `save()` 会把 `target_wpm=0` 写回文件，速度门槛真正丢失。此路径罕见但真实存在。
- **文档更正**：ADR 0010 §4 关于数值类型、档位轮转、预览弹窗快捷键名与存储路径的描述已过时，由本 ADR 部分取代。
- **可发现性（新增入口必须同步改提示）**：`Shift+T` / `Shift+W` 这类「同键 + 修饰键」的入口在终端里天然不可见——按下 `t` 只会轮转档位，用户无从得知大写字母另有用途。因此新增键位必须同步更新三处可见提示，否则功能等于不存在：
  1. 预览弹窗底部提示栏：`Shift+T/W 输入数值`；
  2. 预览面板标题栏目标值段：`[Shift+T/W] 自定义`；
  3. 设置视图对应行的值后缀 `(Enter 输入)` 与底部提示栏 `Enter 自定义输入`。
  README「快捷键指南」的对应表格同步更新。
