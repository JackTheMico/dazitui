# ADR 0016：分章赛文的解析架构与跨会话断点续打

- 状态：提议中 / 研讨完成（2026-09-19）
- 日期：2026-09-19
- 驱动：命令行载入大体积长篇小说（如《道诡异仙.txt》）时的章节自动切分、目录选章跟打与退出断点恢复
- 领域术语：`分章赛文`、`章节目录`、`断点续打`（参见 `CONTEXT.md`）

## 背景

当前 `dazitui` 的离线赛文（`TextSource::File`）将整个本地文件一次性载入单次会话。对于数兆字节、数十万至数百万字的网络小说或长篇书籍（如《道诡异仙.txt》约 6.2MB、966 章），全量载入会导致内存浪费、终端排版过长，且无法满足读者按章节挑选练习、打断退出后精确接续进度的诉求。

## 事实基线

1. **会话级断点支持**：`Session` 已具备 `resumed_chars` 字段与相关逻辑，可将前序字符设为已完成，后续输入从偏移量处接续。
2. **数据库持久化机制**：`dazitui-core::db::Database` 基于 SQLite + WAL 模式，已支持向前兼容迁移，适合管理结构化断点数据。
3. **内置赛文选章交互**：`AppState::BrowsingBuiltin` 提供了基于 Ratatui 的列表浏览与预览模式，具备良好的交互参考价值。

## 决策

| # | 决策点 | 结论 |
|---|---|---|
| D1 | 识别机制 | **自动嗅探（Auto-detect）**：读取文件时自动匹配章节模式（如 `第N章/回/节`、`序/楔子/番外` 等）。有效章节数 $\ge 2$ 时自动判定为分章赛文，否则回退为普通离线赛文。 |
| D2 | 交互入口 | **目录优先（Index-first）**：启动分章赛文时始终先进入「章节目录视图」。初次载入光标聚焦第 1 章；存在历史进度时自动高亮定位至上次退出的章节，按 `Enter` 即可秒级接续。 |
| D3 | 断点粒度 | **字符级精确断点（Character-level）**：持久化保存章节索引与已完成字符偏移量（`resumed_chars`）。再次载入本章时，断点前内容视作已完成，光标直接停在断点字符继续跟打；按 `r` 可重置回章首。 |
| D4 | 存储介质 | **SQLite 表存储**：在 `stats.db` 中新建 `chapter_progress` 表，记录文件规范化绝对路径（`canonicalize`）、章节号、字符偏移量、更新时间。 |
| D5 | 章末与退出流转 | **平滑流转**：整章完成进入成绩视图后，支持按 `n` / `Enter` 快速载入下一章；跟打中按 `Esc` 暂停后按 `c` 可回章节目录；退出时自动同步当前字符断点。 |

## 影响

1. **解耦长文本解析**：在 `dazitui-core` 中新增 `chapter.rs` 模块负责章节模式检测、目录提取与元数据解析，保持核心算法与 TUI 界面解耦。
2. **数据库迁移**：在 `Database::init_pragmas_and_tables` 中增量创建 `chapter_progress` 数据表与索引。
3. **TUI 状态机扩展**：在 `dazitui::main` 的 `AppState` 中引入 `AppState::ChapterCatalog` 状态，统一处理目录浏览、翻页与即时搜索。
