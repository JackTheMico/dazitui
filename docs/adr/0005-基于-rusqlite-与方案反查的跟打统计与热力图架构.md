# 基于 rusqlite 与方案反查的跟打统计与热力图架构

为满足用户对长期跟打练习数据分析（历史 WPM 折线图、按键热力图、高频错字错词排行榜）的需求，确立了以下存储、键位分析、错误归因与 TUI 可视化架构决策。

## 1. 存储引擎选型：rusqlite (bundled + WAL)

经过对 DuckDB 与 SQLite 的深度对比，决定采用 `rusqlite` 作为嵌入式存储引擎：
- **体积与构建轻量**：纯 C 编译，冷编译仅需 5 秒（对比 DuckDB 的 3~4 分钟），二进制增量仅 ~1.5MB（对比 DuckDB 的 ~30MB）；
- **分析能力足够**：SQLite 3.25+ 原生支持标准窗口函数（`AVG(...) OVER (...)`），足以高效完成滚动平均 WPM、历史极值与键频聚合；
- **非阻塞并发**：启用 `PRAGMA journal_mode = WAL;`，支持后台 DB Worker 线程异步持久化练习流水，主 TUI 线程无锁读取，保障 60 FPS 刷新无卡顿；
- **存储路径规范**：遵循 XDG 规范，存储于 `~/.local/share/dazitui/stats.db`。

## 2. 键位分析与方案反查机制 (Reverse Scheme Mapping)

在 Linux (X11/Wayland) 环境下，Fcitx5/IBus 等输入法框架拦截了字母击键，终端仅能捕获到最终确认上屏的汉字字符。为在标准键盘（QWERTY 斜列与直列矩阵）上准确绘制指法热力图：
- **方案反查投射**：基于用户当前配置的输入法方案（虎码、五笔、全拼等），通过内置反查码表将上屏汉字反向分解为字母按键序列；
- **双层热力图系统**：支持按键 `m` 切换“方案反查投射热力图”与“纯物理捕获击键热力图（退格、空格、标点及英文）”；
- **对数平滑归一化**：采用 (k) = \ln(1 + 	ext{count}(k)) / \ln(1 + \max 	ext{count})$ 映射到主题调色板阶梯色，避免高频键（如空格）导致其他键全暗。

## 3. 错词归因策略 (Word Error Attribution)

中文自然文本缺乏空格分隔，为精准统计高频“打错的词”：
- **内置词组赛文**：直接复用编译期内置的原生词边界（`word_boundaries`）；
- **通用/在线/自由赛文**：引入轻量 `jieba-rs` 引擎，在载文时毫秒级建立字符偏移到词汇的映射索引（`CharIndex -> WordToken`），将长度 $\ge 2$ 词汇内的错字精准归因为错词。

## 4. 可视化与交互导航规范 (StatsView & Tabs)

- **导航入口**：功能栏新增 `[数据统计 (s)]` 选项；完成跟打的 `成绩视图` 下亦可按 `s` 直达；
- **三级 Tab 结构**：
  - **Tab 1（WPM 趋势）**：基于 LTTB（最大三角形三桶）时序降采样算法绘制 100~120 点高保真 Braille 折线图，叠加 10 场滚动平滑线；
  - **Tab 2（按键热力）**：支持按 `l` 切换标准斜列（ANSI 60%）与直列矩阵（4x12 Planck / 5x12 Preonic）键盘布局；
  - **Tab 3（错字错词）**：支持按 `t` 切换高频错字 Top 50 与高频错词 Top 50，支持方向键滚动浏览。
