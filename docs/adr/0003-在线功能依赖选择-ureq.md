# 在线功能使用 ureq + feature flag 而非 reqwest

在线功能需要对 52dazi.cn 做 HTTP 调用。在 reqwest（异步、依赖 tokio）与 ureq（同步、无运行时依赖）之间选择了 ureq，并用 Cargo feature flag `online` 控制编译。

## 选择 ureq 的理由

- dazitui 是单线程事件循环应用，不需要 tokio 的异步运行时。引入 tokio 会显著增加编译时间和二进制体积
- 52dazi.cn 的 API 极简单：几个 POST 请求 + JSON 响应，ureq 完全够用（不需要 HTTP/2、流式、连接池等高级特性）
- 同步 I/O 在事件循环里短暂阻塞影响可控——网络延迟远大于 50ms poll 间隔

## 放弃 reqwest 的代价

- 如果未来需要更复杂的 HTTP 特性（如流式下载、代理配置、TLS 自定义），需要迁移回 reqwest
- ureq 社区活跃度不如 reqwest，长期维护风险略高

## Feature flag 设计

在线功能代码集中在 `dazitui-core::online` 模块，由 `Cargo.toml` 的 `online` feature 控制：

```toml
[features]
default = []
online = ["ureq", "aes", "cbc", "base64"]
```

离线场景下（`cargo build` 不带 `--features online`），core 零网络依赖。
